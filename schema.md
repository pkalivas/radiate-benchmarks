# Runner contract

Every language lives in its own top-level directory with a `run.sh`. `main.py` finds
them automatically (any `*/run.sh`), runs them **one at a time**, then merges their
output. This file is the contract a new language has to meet.

## Invocation

```bash
<lang>/run.sh --spec <spec dir> --out <output dir>
```

- `run.sh` builds whatever it needs first (`cargo build --release`, `dotnet build`, ...).
  Build time is never measured.
- Exit codes: `0` ok · `3` toolchain missing, skip this language · anything else = failed.
- Run every problem listed in `spec/config.json` × every seed in `seeds`, for every
  library the language benchmarks.
- A library that doesn't support a problem (e.g. no multi-objective support) just
  writes no rows for it. Don't fake it.

## Input: `spec/`

Generated by `main.py`; never edit it by hand (the aggregator checks `spec_hash`).

`spec/config.json`

| field | meaning |
|---|---|
| `population_size`, `generations` | held equal across every library |
| `crossover_rate`, `mutation_rate` | held equal across every library |
| `seeds` | one run per seed per (library, problem) |
| `problems` | problem names, in run order; each is `spec/problems/<name>.json` |
| `spec_hash` | copy this verbatim into every `runs.csv` row |

`spec/problems/<name>.json` always has `name`, `suite`, `kind` and `minimize`, plus
kind-specific fields. The formulas below are the reference; `radiate_benchmarks/problems/`
implements them in Python, and every other language must match them exactly.

| `kind` | fields | fitness |
|---|---|---|
| `continuous` | `function`, `dim`, `bounds: [lo, hi]` | minimize `function` (sphere, rastrigin, rosenbrock, ackley) |
| `knapsack` | `n_items`, `weights`, `values`, `capacity`, `overweight_penalty` | maximize `Σ value·bit`; if `Σ weight·bit > capacity`, subtract `overweight_penalty · (Σ weight·bit − capacity)` |
| `tsp` | `n_cities`, `coords: [[x, y], ...]` | minimize the Euclidean length of the **closed** tour (includes the last city back to the first) |
| `nqueens` | `n` | minimize the number of diagonally attacking queen pairs; genome is a permutation (`perm[i]` = row of queen in column i) |
| `mo` | `function`, `n_var`, `n_obj`, `bounds`, `ref_point` | minimize every objective of `function` (zdt1, zdt3, dtlz2). The score (hypervolume) is computed by the aggregator |

## Output: three CSVs in `--out`

Plain CSV with a header row. List-valued fields are `;`-joined numbers (`0.25;-1.5;3`),
so fields never need quoting. Write floats at full precision (shortest round-trip form).

### `runs.csv`: one row per (library, problem, seed)

| column | notes |
|---|---|
| `language` | e.g. `python`, `rust`; matches the directory name |
| `library` | e.g. `radiate`, `deap` |
| `library_version` | the version actually benchmarked |
| `problem`, `seed` | from the spec |
| `best_fitness` | best objective value found; **empty for `mo`** |
| `best_solution` | the genes of that best individual (bits as `0`/`1`); **empty for `mo`** |
| `wall_time_s` | see Timing below |
| `spec_hash` | from `spec/config.json` |
| `timestamp` | ISO-8601 UTC, when the run finished |

### `history.csv`: best-so-far per generation (single-objective only)

`language, library, problem, seed, generation, best_so_far`

`generation` starts at 0. `best_so_far` must never get worse from one generation to the next.

### `fronts.csv`: final Pareto front (multi-objective only)

`language, library, problem, seed, point, objectives`

One row per front member; `point` is 0, 1, 2, ...; `objectives` has `n_obj` values, all minimized.

## Timing

`wall_time_s` covers **only the evolution loop**: from just before the first generation
(including initial population evaluation) to just after the last one. It excludes loading
the spec, building the problem, and process start-up. Runtimes with a JIT (.NET, JVM)
should do one untimed warm-up run per (library, problem) before the timed seeds.

## What the aggregator checks

`main.py` merges every `results/<language>/` into `results/master/` and:

- drops rows whose `spec_hash` doesn't match the current spec (stale results);
- **re-scores** each single-objective `best_solution` with the Python reference fitness
  and rejects the row if it doesn't reproduce `best_fitness` (relative tolerance 1e-6).
  This catches a fitness function ported incorrectly to another language;
- computes hypervolume for every multi-objective run from `fronts.csv`, identically for
  all libraries;
- rejects duplicate (language, library, problem, seed) rows.

Rejected rows go to `results/master/rejected.csv` with the reason.
